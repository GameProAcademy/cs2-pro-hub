# H.3-E pre-DEM / post-DEM gates (R5.8.4 matrix, schema 2)

Source of truth: `GATE_SPECS` in `scripts/r5_8_4_gate_reconciliation.py`; this table is generated from it
and `scripts/tests/test_r5_8_4_gate_reconciliation.py::test_gate_doc_matches_the_code` fails if they diverge.

## State machine (per commit of main)

```
PREDEM_BLOCKED --(all 28 pre-DEM gates VERIFIED in one H.3-E activation run)--> READY_FOR_PREDEM_REVIEW
READY_FOR_PREDEM_REVIEW --(operator dispatches A9.1 citing that activation run; same commit, still main head)--> DEM_LAB_RUNNING
DEM_LAB_RUNNING --(A9.1 sealed evidence, bound to the approval)--> POSTDEM_VERIFIED | POSTDEM_FAIL
```

- Pre-DEM never reads post-DEM results; post-DEM results without a valid pre-DEM approval
  (`run_id` and 40-hex `sha`) are turned into FAIL (`POST_DEM_EVIDENCE_WITHOUT_PREDEM_APPROVAL`).
- Missing, malformed or unknown evidence is NOT_PROVEN; nothing defaults to VERIFIED.
- READY_FOR_PREDEM_REVIEW authorizes only the A9.1 laboratory run (isolated runner, no production
  write, `productionAuthorization=false`), never production, Attempt 9 or Canonical.
- R5.8.4 exits non-zero unless every gate it collects (from R5.8.3) is VERIFIED; the activation
  gate adds the gates it proves itself (`remote_ci`, `transport_secret_configured`,
  `endpoint_configured`, `persistence_validation`) and is the pre-DEM arbiter.
