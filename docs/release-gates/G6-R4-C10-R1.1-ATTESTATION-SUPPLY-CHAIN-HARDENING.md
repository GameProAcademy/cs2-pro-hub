## `sandbox_exec` decision

`sandbox_exec` is not a browser-facing application role. Live inspection shows it is login-enabled, has `BYPASSRLS`, and is the internal role through which managed database inspection and migration operations execute. Removing its access would break the approved administrative path and would not create a meaningful client security boundary.

It remains an explicit trusted exception with only `SELECT` and `INSERT` on the nonce and provenance tables. It has no `UPDATE`, `DELETE`, `TRUNCATE`, `REFERENCES`, or `TRIGGER`. Documentation therefore uses **service_role + approved internal sandbox_exec**, not “service-role-only”.

## Supply-chain binding

All five external workflow actions are pinned to immutable upstream commit SHAs. Workflow approval uses the reviewed Git blob SHA of the workflow file, not the commit containing its own allowlist. The Python producer, TypeScript verifier, and database insert trigger independently enforce the approved path and blob SHA. A mismatch returns `ATTESTATION_WORKFLOW_VERSION_NOT_APPROVED` before persistence.

## Evidence status

Local/static tests prove policy behavior; they are not production evidence. HMAC remains unconfigured. GitHub attestation, Railway proof, real DEM execution, Python/WASM parity, four-run determinism, identity, tick authority, and forensic integrity remain `NOT VERIFIED` or `NOT RUN`. The final gate therefore remains blocked by design.
